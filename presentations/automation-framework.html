📐 Page Object Model (POM)

Structure

// src/pages/LoginPage.ts export class LoginPage extends BasePage { async login(user: string, pass: string) { await this.page.fill('[name=username]', user); await this.page.fill('[name=password]', pass); await this.page.click('[type=submit]'); await this.page.waitForURL('/dashboard'); } } // tests/auth/login.spec.ts test('login with valid credentials', async ({ loginPage }) => { await loginPage.login('Admin', 'admin123'); await expect(page).toHaveURL(/dashboard/); });

Key Principles

  • 1
    One class per page — LoginPage, DashboardPage, EmployeePage each own their selectors and actions.
  • 2
    BasePage provides shared utilities: navigation, waits, toast reading, screenshot helpers.
  • 3
    Tests are selector-free — no locators in test files; tests describe behaviour, pages handle mechanics.
  • 4
    Single point of change — if a selector changes, update one method in one class, not 50 test files.
Result: Tests read like acceptance criteria — easy for non-engineers to review and validate.

🚀 How to Run

Setup

# 1. Clone and install git clone github.com/qaabhayraj-cpu/DemoPlaywriteAI-AutomationProject npm ci npx playwright install # 2. Configure environment cp config/environments/qa.env .env

Playwright Tests

# Smoke gate (fast — 2 min) npm run test:smoke # Full regression npm run test:regression # By browser npm run test:chrome npm run test:firefox npm run test:webkit # API tests only npm run test:api # Visual + A11y npm run test:visual npm run test:a11y

Performance Tests

# One-time JMeter setup npm run perf:setup # Run login load test npm run perf:login # Custom: 10 users, 5 loops bash jmeter/scripts/run.sh login \ -Jthreads=10 -Jloops=5 -Jramp_up=30 # Open HTML dashboard npm run perf:report:login # Generate PDF npm run perf:pdf

Reports

# Playwright HTML report npm run report # Allure report npm run report:allure npm run report:open

DemoPlaywriteAI-AutomationProject/ ├── src/ │ ├── pages/ ← Page Object Model │ ├── fixtures/ ← Dependency injection │ ├── api/ ← REST API client │ ├── helpers/ ← Utilities & data │ └── types/ ← TypeScript interfaces ├── tests/ │ ├── smoke/ ← Fast CI gate │ ├── auth/ ← Login tests │ ├── employee/ ← CRUD tests │ ├── api/ ← API tests │ ├── visual/ ← Screenshot diff │ ├── a11y/ ← WCAG compliance │ └── network/ ← Request mocking ├── jmeter/ │ ├── test-plans/ ← login.jmx │ └── scripts/ ← setup, run, pdf, email ├── config/ │ └── environments/ ← dev / qa / staging ├── .github/workflows/ ← CI/CD pipelines └── playwright.config.ts

📁 src/ — Framework Core

All reusable logic: page objects, API clients, helpers, type definitions. Tests never contain selectors or raw fetch calls.

📁 tests/ — Test Suites

Pure test logic — describe what should happen, not how. 7 test types, each in its own folder.

📁 jmeter/ — Performance

Self-contained load testing suite: plans, scripts, and auto-generated results/reports folders.

📁 config/ — Environments

dev.env / qa.env / staging.env — switch environments with a single env var: TEST_ENV=staging npm test
